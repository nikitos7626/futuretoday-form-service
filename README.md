# Сервис создания форм откликов 

Компактный веб-сервис на архитектуре **MVC** (Node.js Express + SQLite). Позволяет создавать динамические анкеты соискателей, генерировать персональные ссылки, отслеживать телеметрию заполнения в реальном времени и анализировать воронку отвалов (Drop-off Rate).

---

## ⚡ Быстрый старт

Проект спроектирован по принципу **Zero-Build**: никаких сборщиков (Vite/Webpack) и внешних баз данных. Запускается «из коробки» двумя командами:

### 1. Установка зависимостей
```bash
npm install
```

### 2. Запуск приложения
```bash
npm start
```

После запуска сервис моментально доступен:
- **Панель управления (Admin Dashboard):** [http://localhost:3000/admin](http://localhost:3000/admin)
- **Форма соискателя (Candidate Form):** `http://localhost:3000/s/<slug>`

## ⚙️ Конфигурация (.env)

Параметры окружения вынесены в файл `.env` в корне проекта:
```env
PORT=3000
DB_PATH=./data/surveys.db
```
Если переменная `PORT` не задана, по умолчанию используется порт `3000`.

## 🏗️ Архитектура проекта (Classic MVC)

Проект строго следует принципу разделения ответственности (**Single Responsibility Principle**):

```text
future_todayV2/
├── data/                      # Локальная база SQLite (WAL-режим)
├── src/
│   ├── config.js              # Конфигурация портов и путей
│   ├── db.js                  # Инициализация SQLite и Graceful Shutdown (closeDatabase)
│   ├── models/                # [M] MODEL: работа с базой данных
│   │   ├── surveyModel.js     # CRUD опросов, поиск по slug и content_hash
│   │   └── responseModel.js   # Сессии соискателей, телеметрия, аналитика отвалов
│   ├── controllers/           # [C] CONTROLLER: обработка HTTP-запросов
│   │   ├── surveyController.js # Валидация, дедупликация и выдача анкет
│   │   └── responseController.js # Сессии, автосохранение, сабмит откликов
│   ├── routes/                # Роутинг эндпоинтов
│   │   └── apiRoutes.js       # Декларативная привязка URL к контроллерам
│   ├── utils/                 # Утилиты
│   │   └── hash.js            # Канонизация структуры анкет и SHA-256 дедупликация
│   ├── public/                # [V] VIEW: Клиентский интерфейс (Hallmark Cobalt)
│   │   ├── admin.html         # Панель конструктора и live-аналитики
│   │   ├── survey.html        # Пошаговая форма соискателя
│   │   ├── css/style.css      # Чистый CSS на дизайн-токенах (:root, IBM Plex Sans)
│   │   └── js/
│   │       ├── admin.js       # Клиентская логика админки и поллинга
│   │       └── survey.js      # Автосохранение черновика (localStorage + API)
│   ├── app.js                 # Сборка Express-приложения (~40 строк)
│   └── server.js              # Точка входа с перехватом SIGINT/SIGTERM
├── test/                      # Автотесты (Node.js test runner)
│   ├── api.test.js            # Интеграционные тесты API

├── AI_COLLABORATION_LOG.md    # Подробный лог парной разработки с ИИ
```

## 🧠 Ключевые архитектурные решения и компромиссы

### 1. Выбор SQLite (`better-sqlite3`) с режимом WAL
* **Решение:** Вместо развертывания тяжелых клиент-серверных СУБД (PostgreSQL/MySQL) использован встроенный движок SQLite в режиме `WAL` (Write-Ahead Logging).
* **Обоснование:** Полная автономность проекта — проверяющему не нужно настраивать Docker или локальные службы. База разворачивается автоматически в локальном файле при первом старте.

### 2. JSON-модель для динамических вопросов и ответов
* **Решение:** Схема вопросов (`questions`) и ответы соискателя (`answers`) хранятся в виде структурированного JSON.
* **Обоснование:** Конструктор анкет оперирует динамическими полями (текст, радиокнопки, чекбоксы, шкалы). Попытка разложить это на классические реляционные таблицы привела бы либо к генерации динамических таблиц в рантайме (`ALTER/CREATE TABLE`), либо к антипаттерну EAV (Entity-Attribute-Value), требующему десятков `JOIN`-ов на один запрос. JSON-документ обеспечивает идеальную гибкость.

### 3. Защита от потери данных соискателя (`session_uuid`)
* **Решение:** При открытии формы в браузере генерируется `session_uuid` и кэшируется в `localStorage`.
* **Обоснование:** Если студент случайно закроет вкладку или обновит страницу на 10-м вопросе, все его введённые данные и текущий шаг моментально восстанавливаются.

### 4. Расчёт аналитики отвалов (Drop-off Rate)
* **Решение:** В таблице `responses` каждое промежуточное действие фиксирует `current_step` и `progress`.
* **Обоснование:** Позволяет строить точную воронку отвалов одним простым SQL-запросом по незавершённым сессиям (`status = 'in_progress'`), мгновенно выявляя вопросы, на которых кандидаты бросают анкету.

### 5. Дедупликация вакансий по хэшу содержимого (Content-Addressable Hashing)
* **Решение:** Утилита `hash.js` нормализует заголовок и структуру вопросов (сортировка ключей, удаление лишних пробелов) и вычисляет SHA-256 хэш.
* **Обоснование:** Предотвращает случайное создание идентичных дубликатов анкет разными HR-менеджерами.

### 6. Дизайн-система Hallmark Cobalt (Anti-AI-slop)
* **Решение:** Отказ от Bootstrap/Tailwind/AntD в пользу чистого CSS по методологии [Hallmark](https://github.com/nutlope/hallmark).
* **Обоснование:** Интерфейс загружается за доли миллисекунды, выглядит строго и профессионально (палитра `oklch`, типографика `IBM Plex Sans`, тактильные keycaps-кнопки), полностью исключая типичные нейросетевые артефакты (мыльные градиенты и лишние тени).
